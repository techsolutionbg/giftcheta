# Giftcheta architecture

Giftcheta is a modular monolith with a small plain PHP 8.3+ backend. Apache serves only `public/`; all requests enter through `public/index.php` and pass through the application middleware pipeline to a route/controller. Controllers return immutable HTTP responses; API payloads use `data` or `error` envelopes.

Configuration is loaded from environment variables into PHP config files. `Database` creates a PDO MySQL connection with exceptions, associative fetches, and native prepared statements. CLI migrations are sorted SQL files recorded in the `migrations` table. MySQL DDL can partially apply, so a failed migration reports that manual inspection is needed; migrations are not falsely treated as transactional.

Logs go to private `storage/logs`. Health is public and intentionally reveals only `ok`. Status is available only when `APP_ENV=development`. Production should point the domain document root to `public/`; for cPanel accounts that cannot change the root, publish a carefully assembled public directory and place the application source/config/storage above `public_html`, with a reviewed bootstrap path. Never copy the whole repository into `public_html`.

The future storefront remains PHP-rendered. A separately built React/TypeScript admin places compiled assets under `public/admin`; Node is a build-time tool only. The admin includes catalog, preferences, customer-contact management, password recovery for existing customer accounts, and order management. Customer contacts and addresses remain behind admin permissions; there is no customer login, public registration, or customer portal. Orders support guest/customer snapshots, immutable item and address details, and must not cascade-delete historical order records when a customer or catalog record is deleted.

Order creation recalculates prices server-side and commits the order, snapshots, status history, email outbox entries, and inventory deductions in one transaction. Tracked stock changes use the existing product stock movement ledger. Cancellation restores tracked stock at most once. Email delivery is retried through a bounded outbox policy; SMTP errors do not roll back a committed order. The admin order module does not implement public checkout, payment-gateway integration, automated tax, discounts, or a shipping-rate service. Shipping is entered manually per order until those policies are configured.
